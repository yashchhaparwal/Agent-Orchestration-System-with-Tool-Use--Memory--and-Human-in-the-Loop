What Phase 3 delivered
The full tool layer — five MCP servers now stand behind the registry. The three new ones each carry a specific safety property by construction:

Sandbox (run_python): every call is a fresh container with network_mode=none, a read-only root filesystem with a tmpfs /work, all capabilities dropped, no-new-privileges, an unprivileged user, memory/CPU/PID limits, a kill on timeout, and guaranteed removal. Built from infra/sandbox/Dockerfile via make sandbox-image.
Web (search, fetch): search behind a backend protocol (deterministic fixtures by default); fetch with an SSRF guard that resolves DNS itself, rejects loopback/private/link-local ranges, re-checks every redirect hop, refuses credentials in URLs, and honours an optional allow-list.
Actions (send_email, create_calendar_event, call_api): validate and write an outbox row. There is no code path that sends anything — destructive actions are gated twice, by the human at the gate and the human who drains the outbox.
The gate, completed — decide_async applies the full algorithm: unknown tool / wrong agent / bad arguments / rate limit → block; safe → allow; destructive → a human, always; risky → a small LLM classifier decides whether a human needs to look, and any classifier failure means approve. A Redis-backed rate limiter shares budgets across workers and fails closed. Every gated call becomes a ToolEvent (arguments hashed, never stored) and lands in a tool_invocations ledger the API exposes.

Verification — 132 unit tests, ruff and mypy clean. The live acceptance test against all five servers, Redis, Postgres and Docker passed 4/4: eleven tools registered; an unauthorised call blocked with its reason; a destructive call stopped at the gate and producing only an outbox row when invoked directly; and the sandbox proving itself — NETWORK_BLOCKED, a pandas computation returning the right answer, a hung script killed after 3 s, a write to /etc/hostname refused. Phase 4 — human-in-the-loop: done and committed (68d04ab)
What was built (56 files; all under the "$0, no artifacts, no AgentLens" constraints)

Pausable agent loop — when the gate says approve, the loop serialises its messages, pending calls and ledgers into a LoopCheckpoint in graph state and returns; on resume it continues from that exact turn, so no model call is ever replayed. This avoided LangGraph's node re-execution problem that a naive interrupt() inside the loop would have caused.
Three interrupt nodes — await_approval (L2 tool calls), approve_plan (L3), escalate (L4) — each with approve / modify / reject / take-over. Approval rows are idempotent, decisions are single-shot (409), reject needs a reason (422), and timeouts can only reject or cancel.
Persistence, worker, API, UI — approvals table + migration, resume_task + beat expire_approvals, /v1/approvals* + /v1/outbox, and a Streamlit operator console (queue, context package, four decisions, tasks, outbox) at apps/review_ui/.
Verified: 167 unit tests (whole decision matrix with fakes, loop pause/resume, policy/store/timeouts, API, headless Streamlit pages), 3 Postgres resume integration tests, mypy --strict and ruff clean.
